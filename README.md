# Edulet

교실·연수에서 쓰는 **실시간 협업 게시판**입니다. 보드 하나를 열어 두고 여럿이 글·이미지·파일·링크를 올리고, 댓글과 반응을 달고, 카드를 끌어 정리합니다. 한 사람이 올린 글은 **새로고침 없이** 모두의 화면에 나타납니다.

- **의존성 0개.** Node 내장 모듈(`http`, `node:sqlite`, `crypto`)만 씁니다. `npm install` 없이 바로 실행됩니다.
- 프런트는 **빌드 없는 ES 모듈**(프레임워크 없음), 실시간은 **SSE**, 저장은 **SQLite 파일 하나**입니다.
- 서버 단위·통합 테스트와, 격리된 크롬 여러 개로 서로 다른 사용자를 흉내 내는 **E2E 수락 시나리오**가 함께 들어 있습니다.

![캔버스 형식](docs/screens/canvas.png)

## 빠른 시작

Node.js **22.13 이상**이 필요합니다.

```bash
npm start            # http://localhost:3000
```

Windows 에서는 `run.cmd` 를 더블클릭해도 됩니다(브라우저가 같이 열립니다). 처음 시작하면 데모 보드(연습장)가 만들어집니다.

| 주소 | 내용 |
|---|---|
| `/b/practice` | 누구나 글을 올려 볼 수 있는 **연습장**(벽 형식). 창을 두 개 나란히 열고 실시간 동작을 확인해 보세요 |

회원가입 없이도 보드 주소로 들어가 이름만 입력하면(게스트) 참여할 수 있습니다. 보드를 만들려면 가입·로그인이 필요합니다.

Docker:

```bash
docker build -t edulet .
docker run -p 3000:3000 -v edulet-data:/data edulet
```

## 다른 PC 와 함께 쓰기

교실·연수실처럼 **같은 와이파이/유선망**에 있는 PC·휴대폰이 한 보드를 함께 쓰려면, **보드를 여는 PC 한 대에서 서버를 켜고** 나머지는 그 PC 의 주소로 들어오면 됩니다. 서버의 기본 `HOST` 가 `0.0.0.0` 이라 따로 설정할 것이 없고, 들어온 사람은 가입 없이 이름만(또는 **"이름 없이 바로 참여"** 한 번으로) 글·댓글을 쓰며 모두의 화면에 새로고침 없이 나타납니다.

> 한 장짜리 안내(유선·무선, IP 가 바뀌는 경우, 저장하기·불러오기, HTML 파일로 내보내기 포함): [`docs/server-mode.html`](docs/server-mode.html) — 내려받아 브라우저로 열면 됩니다.

1. 서버를 켤 PC 에서 `run.cmd` 를 더블클릭하거나 `npm start` 를 실행합니다. 서버 창에 **"같은 네트워크의 다른 기기에서는: http://192.168.0.12:3000"** 처럼 이 PC 의 네트워크 주소가 한 줄 나옵니다(주소 숫자는 PC 마다 다릅니다).
2. 평소처럼 `http://localhost:3000` 으로 열어 보드를 만들고 **공유**를 누릅니다. 링크와 QR 코드가 `localhost` 가 아니라 위 **네트워크 주소**로 만들어집니다(PC 에 네트워크 연결이 여러 개면 공유 창의 "공유할 주소"에서 함께 쓸 사람과 같은 네트워크의 주소를 고르세요). 공개 범위가 **링크가 있는 누구나**(기본)이면 로그인 없이 들어올 수 있고, 링크 권한이 **댓글**(기본)이면 댓글과 반응을, **글쓰기**로 올리면 글도 올릴 수 있습니다.
3. 다른 PC 에서는 링크를 열고, 휴대폰에서는 QR 코드를 카메라로 스캔합니다. 교실 화면에 공유 창을 띄워 두면 한꺼번에 입장하기 좋습니다.

열리지 않을 때:

- **Windows 방화벽** — 서버를 처음 켜면 "Windows Defender 방화벽이 이 앱의 일부 기능을 차단했습니다"가 뜹니다. **개인 네트워크**(집·학교)에 체크하고 **액세스 허용**을 누르세요. 놓쳤다면 Windows 보안 → 방화벽 및 네트워크 보호 → "방화벽을 통해 앱 허용"에서 **Node.js JavaScript Runtime** 의 개인 네트워크를 켭니다.
- **같은 네트워크인지** — 서버 PC 와 상대 기기가 같은 공유기·같은 와이파이에 있어야 합니다. 학교 와이파이가 기기끼리의 통신을 막는 경우(AP 격리)나 손님용 와이파이는 안 열립니다. 이때는 서버 PC 도 상대와 같은 와이파이/유선망에 두세요. VPN 이 켜져 있으면 끄고 다시 해 보세요.
- **서버 PC 가 켜져 있고 절전 상태가 아닌지** — 서버를 켠 창을 닫거나 PC 가 잠들면 모두의 연결이 끊깁니다.
- **주소(IP)가 바뀌었는지** — 무선(와이파이)은 다시 연결하거나 절전에서 깨어나거나 공유기를 다시 켜면 PC 의 주소가 바뀔 수 있습니다(유선도 공유기 설정에 따라 바뀝니다). 서버 창에 처음 나온 주소는 서버를 켤 때의 값이라 낡았을 수 있어요. **공유 창을 열 때마다 현재 주소를 다시 읽어** 링크·QR 을 새로 만들므로(주소가 바뀌었으면 알려 줍니다), 안 열린다는 사람이 있으면 공유 창을 다시 열어 새 QR 을 보여 주세요. 수업 중에 주소가 바뀌면 이미 퍼뜨린 링크는 못 쓰니, 주소를 고정하려면 공유기에서 이 PC 에 **고정 IP(DHCP 예약)** 를 주거나 **유선**으로 연결하세요.
- 공유 창에 "이 PC 에서만 열려요" 경고가 보이면 서버가 이 PC 의 네트워크 주소를 찾지 못한 것입니다(`EDULET_HOST=127.0.0.1` 로 켰거나 네트워크에 연결돼 있지 않음). 서버 창에 나온 주소로 다시 열어 보세요.

**인터넷으로 공개**하려면(서로 다른 네트워크에서 접속) 바깥에서 열 수 있는 공개 주소가 필요합니다. Cloudflare Tunnel·ngrok 같은 **터널**로 내 PC 의 3000 포트를 열거나, Docker 로 클라우드/학교 서버에 올리세요(빠른 시작의 Docker). 이때는 서버에 주소를 알려 줘야 링크·QR 이 그 주소로 만들어집니다.

```bash
EDULET_PUBLIC_URL=https://edulet.example.com EDULET_TRUST_PROXY=1 EDULET_COOKIE_SECURE=1 npm start
# Windows 명령 프롬프트: set EDULET_PUBLIC_URL=https://edulet.example.com  (줄마다 set 한 뒤 npm start) · PowerShell: $env:EDULET_PUBLIC_URL='https://edulet.example.com'
```

- `PUBLIC_URL` — 사람들이 접속하는 주소(원점만, 경로·끝 슬래시 없음). 있으면 공유 링크·QR 이 항상 이 주소로 나옵니다. `http://localhost:3000` 처럼 이 PC 자신을 가리키는 값(Google 로그인 시험용)은 공개 주소로 치지 않아, 위 네트워크 주소 안내가 그대로 동작합니다. **리버스 프록시(nginx 등)가 같은 PC 에서 서버로 전달하는 구성에서는 `PUBLIC_URL` 을 꼭 넣거나 `EDULET_HOST=127.0.0.1` 로 서버를 프록시에만 열어 두세요** — 그래야 서버의 내부 주소가 방문자에게 안내되지 않습니다.
- **Docker** — 컨테이너 안에서는 서버가 자기 네트워크 주소를 알 수 없어, 같은 PC 에서 `localhost` 로 열면 공유 창에 "이 PC 에서만 열려요" 경고가 뜹니다. 호스트 PC 의 주소(서버 PC 의 `ipconfig` 에 보이는 IPv4)로 열거나 `EDULET_PUBLIC_URL` 에 그 주소를 넣어 주세요.
- `TRUST_PROXY=1` — 터널·리버스 프록시 뒤에서 접속자 IP 와 HTTPS 를 `X-Forwarded-*` 로 판별하게 합니다(게스트 입장 한도가 접속자별로 걸립니다). 프록시가 없는데 켜면 헤더를 위조할 수 있으니 터널/프록시 뒤에서만 켭니다.
- `COOKIE_SECURE=1` — HTTPS 로만 쓰는 공개 서버에서 로그인 쿠키에 `Secure` 를 붙입니다(`PUBLIC_URL` 이 https 면 `auto` 가 자동으로 켭니다). http 로 시험할 때는 켜지 마세요.
- 프록시에서 SSE 경로(`/api/boards/*/events`)의 응답 버퍼링을 끄세요(nginx: `proxy_buffering off;`). 아래 설정 표도 참고하세요.

> **GitHub Pages 데모는 이 방법으로 다른 기기와 공유할 수 없습니다.** 데모는 서버 없이 방문자 **브라우저 안**(서비스 워커 + IndexedDB)에서만 돌아서, 보드와 글이 그 브라우저에만 있습니다. 데모의 공유 창에 링크·QR 이 보여도 다른 PC·휴대폰에서 열면 그 보드가 없습니다(공유 창에도 같은 안내가 나옵니다). 여럿이 함께 쓰려면 위처럼 서버를 켜세요.

## 보드를 HTML 파일로 내보내기 (오프라인에서 열어 보기)

보드 한 장의 글·댓글·반응·사진·첨부를 **파일 하나(`edulet-보드주소-날짜.html`)** 로 내려받아, 인터넷·서버 없이 **더블클릭만으로** 열어 볼 수 있습니다. 수업이 끝난 뒤 보관하거나 메일·USB 로 건넬 때 쓰세요. 서버 모드와 GitHub Pages 데모 모두에서 됩니다.

- **어디서**: 보드 화면 위쪽의 **내보내기** 버튼(아주 좁은 화면에서는 **공유 → 내보내기·복제**), 또는 내 보드 카드의 **⋯ → HTML 로 내보내기**. 공유 창의 내보내기 구역에서는 옵션을 고를 수 있고 진행 상황·취소가 보입니다.
- **무엇이 담기나**: 보드 형식(벽·격자·스트림·선반·행·캔버스·채팅)에 맞춘 읽기 전용 화면, 섹션, 카드(제목·본문·작성자·시각·색), 첨부 사진(눌러서 크게), 반응 개수, 댓글. 업로드한 PDF 같은 파일은 내려받기 링크로, 업로드한 동영상·소리는 재생기로 담깁니다.
- **그림 크기 옵션**: 기본은 긴 변 1600px 이하로 줄여 담습니다(파일이 작아지고 사진의 **위치 정보(EXIF)도 빠집니다**). **원본 크기**를 고르면 그림이 그대로(위치 정보 포함) 들어갑니다. 움직이는 그림(APNG·WebP)은 기본에서 정지된 그림이 됩니다(GIF 와 원본 크기에서는 그대로).
- **한도**: 파일 하나 15MB·첨부 합계 150MB·글자 합계 100MB, 그림 한 장은 약 4천만 화소까지. 넘거나 열 수 없는 파일은 **"담지 못한 파일"** 로 파일 안과 끝난 뒤 요약에 표시됩니다(조용히 빠지지 않습니다). 글자 한도를 넘으면 불완전한 파일을 만들지 않고 안내와 함께 멈춥니다. 만든 파일이 20MB 를 넘으면 메일 첨부가 어려울 수 있다고 알려 줍니다.
- **담기지 않는 것**: 다른 사이트의 그림(링크 미리보기 썸네일)과 YouTube·Vimeo 영상은 인터넷이 필요해 **링크 글자로만** 남습니다. 파일을 열 때 어떤 외부 접속도 하지 않습니다.
- **안전**: 파일에는 **스크립트가 한 줄도 없고** 외부 접속을 막는 보안 설정(CSP)이 들어 있습니다. 학생이 쓴 글에 악성 입력이 있어도 파일을 열 때 실행되지 않습니다. 링크는 `http(s)` 만 열립니다.
- **누가 무엇을 받나**: 내보내는 사람에게 **보이는 내용만** 담깁니다(작성자 숨김 보드는 이름이 빠지고, 관리자가 내보내면 승인 대기 중인 글도 담깁니다). 사진과 글 전부가 파일 안에 있으니 **다른 사람에게 보낼 때 주의**하세요. 파일 자체는 서버나 `backups` 와 무관한 보통 파일입니다. (JSON·CSV 내보내기는 그대로 있습니다 — 엑셀로 열려면 CSV.)

## 백업과 복원

### 화면에서 저장하기·불러오기 (가장 쉬운 방법)

서버를 켠 PC 에서 `http://localhost:3000` 처럼 **`localhost` 주소로 Edulet 을 열면** 위쪽 막대에 **저장하기**와 **불러오기**가 보입니다. 로그인한 뒤에는 이름 옆 메뉴(▾)에도, 보드 화면에서도 같은 항목이 있습니다. 서버를 끄지 않고 수업 중에도 쓸 수 있습니다.

| 메뉴 | 하는 일 |
|---|---|
| **저장하기** | **[지금 저장]** 한 번으로 모든 보드·글·계정·사진·파일을 `backups` 폴더에 새 폴더(`edulet-날짜-시간`)로 저장합니다. 끝나면 저장한 때·개수·폴더 이름과, 알아 둘 점(경고)이 있으면 눈에 띄게 알려 줍니다 |
| **불러오기** | 저장본 목록(최신 순)에서 하나를 고르면 ① **미리보기**(보드 목록, "저장본 글 11개 ↔ 지금 글 14개 — 불러오면 3개 적어져요" 같은 지금과의 차이) → ② **확인** → ③ 불러오기 순서로 진행합니다. 끝나면 화면이 저절로 새로고침됩니다 |

- **불러오기 직전에 지금 데이터를 먼저 자동으로 저장**합니다. 목록에 **자동 저장**이라는 이름표가 붙은 저장본이 하나 더 생기니, 잘못 불러왔어도 그것을 고르면 바로 되돌릴 수 있습니다.
- 불러오면 **계정·비밀번호도 저장 당시로 돌아갑니다**(그 뒤에 바꾼 비밀번호는 원래대로). 저장본에 있던 계정으로 다시 로그인해야 할 수 있고, 그때는 화면이 알려 줍니다. 지금 이 서버에 접속해 있는 다른 기기의 화면도 함께 새로고침됩니다.
- 불러오는 동안(데이터가 많으면 몇 초) 글쓰기·수정이 잠깐 멈추고 서버가 잠시 느려질 수 있습니다. 저장도 사진이 아주 많으면 몇 초 걸립니다.
- 저장본 폴더는 서버 PC 의 `backups`(저장소 폴더 안; 위치를 바꾸려면 `EDULET_BACKUP_DIR`)에 있습니다. **새 PC 로 옮길 때**는 옛 PC 의 `backups\edulet-…` 폴더를 새 PC 의 `backups` 안에 복사하면 불러오기 목록에 나타납니다. 새 PC 에서도 처음 켤 때 연습용 보드가 만들어지는데 그 주인이 "계정"으로 세어지므로, **처음 한 번 교사 계정을 가입해 로그인한 뒤에** 불러올 수 있습니다(계정이 생긴 뒤에는 로그인한 계정으로만). 불러오면 임시로 가입한 계정은 저장본의 계정으로 바뀌니 저장본의 계정으로 다시 로그인하세요.
- **메뉴가 안 보이는 것이 정상인 경우**: 서버 PC 가 아닌 다른 기기·같은 네트워크의 주소(`http://192.168.…`)로 연 화면, 프록시·터널(ngrok 등)을 거친 접속, GitHub Pages 데모. 공개 주소(`EDULET_PUBLIC_URL`)를 설정해 공개 운영하는 서버에서는 서버 PC 에서 `localhost` 로 열어도 보이지 않으니 아래 `backup.cmd` 로 저장하세요.
- **보안**: 저장본에는 비밀번호 해시·로그인 세션·모든 글이 들어 있는 **민감한 자료**입니다. 깃허브·메신저·공유 폴더에 올리지 마세요(저장소의 `.gitignore` 가 `backups/` 를 막아 줍니다). 공용 PC 처럼 학생과 같이 쓰는 서버 PC 에서는 **그 PC 에서 가입한 누구나** 저장·불러오기를 할 수 있으니 `EDULET_ALLOW_REGISTER=0`(새 가입 막기)을 권장합니다.
- 보드 한 장만 파일로 가져가려면 **내보내기**를 쓰세요 → [HTML 파일로 내보내기](#보드를-html-파일로-내보내기-오프라인에서-열어-보기). 이 절의 저장하기·불러오기는 서버 전체의 백업입니다.

### 명령줄로 백업하기 · 손으로 복원하기 (화면을 쓸 수 없을 때)

데이터(보드·글·계정·업로드 파일)는 모두 `data` 폴더에 있습니다. **서버를 켜 둔 동안 `data\edulet.db` 는 낡은 값**(비어 있거나 최근 작업이 빠진 파일)이고 최근 작업은 `edulet.db-wal` 에 쌓여 있어서, **켜 둔 채 `edulet.db` 만 복사하면 그 작업이 빠진 백업**이 됩니다. 서버를 끄지 않고 백업하려면:

```bash
backup.cmd                                  # Windows: 더블클릭 (서버를 켠 채로 해도 안전)
node tools/backup.mjs [--data <폴더>] [--out <폴더>]
```

- `backups\edulet-YYYYMMDD-HHMMSS\` 폴더가 새로 생기고 `edulet.db`(WAL 안의 최신 내용까지 담은 하나의 파일), `uploads\`(올라온 파일), `BACKUP-INFO.txt`(만든 시각·개수·**복원 방법**)가 들어갑니다. 같은 초에 또 하면 `-2`, `-3`.
- **정상 이름의 폴더는 끝까지 만들어 확인을 마친 것만 있습니다.** 작업은 `edulet-….partial` 폴더에서 하고 마지막에 이름을 바꾸므로, **이름 끝에 `.partial` 이 붙은 폴더는 중간에 끊긴 것**(창 닫기·전원 차단)이니 쓰지 말고 지워도 됩니다(자동으로 지우지는 않습니다).
- **원본은 읽기만 합니다**(SQLite `VACUUM INTO` — 서버가 읽고 쓰는 중에도 한 시점의 일관된 스냅샷). 단 서버가 꺼진 `data` 를 읽으면 SQLite 가 빈 `edulet.db-wal`·`edulet.db-shm` 을 새로 만들 수 있습니다(`edulet.db` 는 그대로, 다음 서버 시작이 알아서 씁니다). 만든 백업은 `integrity_check` 로 확인하고, 하나라도 어긋나면 그 백업 폴더만 지우고 실패로 끝냅니다.
- **종료 코드** `0` 완전한 백업 · `1` 실패(만들던 폴더는 지움) · `2` 백업은 만들었지만 경고가 있음(일부 파일이 빠졌을 수 있음 — 폴더는 남고, 화면 맨 위에 "주의:" 가 나옵니다). `backup.cmd` 는 끝에 각각 아무 말 없음 · `Backup FAILED` · `Backup finished WITH WARNINGS` 를 보여 줍니다.
- **엉뚱한 `data` 를 백업하지 않았는지** 끝날 때 보여 주는 `원본 폴더 · 가장 최근 글 · 원본 WAL 마지막 수정` 으로 확인하세요(글이 하나도 없으면 경고). `--data` 기본값은 환경변수 `EDULET_DATA_DIR`, 없으면 **이 저장소의 `data`** 입니다 — 서버의 `./data`(= 서버를 시작한 폴더 기준)와 일부러 다릅니다. **서버를 `EDULET_DATA_DIR` 로 켰다면 `backup.cmd` 를 실행하는 쪽에도 같은 환경변수가 필요**하고, 서버를 다른 폴더에서 켰다면 그 `data` 를 `--data` 로 알려 주세요. `--out` 기본값은 저장소의 `backups`(`.gitignore`·`.dockerignore` 에 있음 — `edulet-날짜-시간*` 폴더는 어디에 만들어도 커밋되지 않습니다. 비밀번호 해시·세션이 들어 있으니 올리지 마세요). `--out` 을 `data` 안에 둘 수는 없습니다.
- `data\uploads` 가 다른 드라이브로 이어진 바로가기(링크·정션)면 따라가서 백업하고 경고로 알립니다. 업로드 파일 하나가 바로가기이거나 다른 프로그램이 잠그고 있으면(몇 번 다시 시도한 뒤) 그 파일만 건너뛰고 경고합니다. 오류 메시지는 한 줄이며, 자세한 스택이 필요하면 환경변수 `EDULET_DEBUG=1`.
- **복원**: `BACKUP-INFO.txt` 가 있는 정상 이름의 폴더로 — 서버를 끄고 → 지금의 `data` 폴더를 따로 옮겨 두고 → 새 `data` 폴더에 백업의 `edulet.db` 와 `uploads` 를 복사하고 → **그곳에 옛 `edulet.db-wal`·`edulet.db-shm` 이 있으면 반드시 지운 뒤**(남아 있으면 다른 데이터베이스의 기록이 복원본에 재생돼 손상됩니다) → `run.cmd`. 자세한 안내는 [`docs/server-mode.html`](docs/server-mode.html) 4번.
- 아직 "게시하기"를 누르지 않은 작성 중인 글은 브라우저 메모리에만 있어 백업에 담기지 않습니다.
- Docker 이미지에는 `tools` 가 들어 있지 않습니다(`.dockerignore`). 컨테이너를 **멈춘 뒤** 볼륨의 `data` 를 복사하세요.

## 설정(환경변수)

모두 `EDULET_` 접두사입니다.

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` / `HOST` | `3000` / `0.0.0.0` | 접속 주소 |
| `DATA_DIR` | `./data` | DB(`edulet.db`)와 업로드 파일 위치 — **백업은 이 폴더만**(서버를 켠 채로는 `backup.cmd`, 끈 뒤에는 폴더 통째로 복사 — [백업과 복원](#백업과-복원)). `./data` 는 **서버를 시작한 폴더 기준**이라 `run.cmd` 는 먼저 자기 폴더로 이동해 시작합니다. `node server\index.js` 를 다른 폴더에서 직접 켜면 그 폴더에 새 빈 `data` 가 생기니, 위치를 고정하려면 절대 경로를 넣으세요(예: `EDULET_DATA_DIR=D:\EduletData`). 껐다 켠 뒤 이어 쓰기·백업·복원은 [`docs/server-mode.html`](docs/server-mode.html) 4번 |
| `BACKUP_DIR` | 저장소의 `backups` | 화면의 **저장하기**가 만들고 **불러오기**가 읽는 폴더([백업과 복원](#백업과-복원)). 저장소 폴더 기준(서버를 시작한 폴더와 무관) · `data` 폴더 안은 안 됩니다 |
| `SEED` | `auto` | `auto` = DB 가 비었을 때만 데모 보드 생성, `0` = 끄기, `1` = 항상 |
| `ALLOW_REGISTER` | `1` | `0` 이면 가입 막기(기존 계정·게스트만 — Google 로 새로 가입하는 것도 막힙니다) |
| `GOOGLE_CLIENT_ID` · `GOOGLE_CLIENT_SECRET` | 없음 | **둘 다 있으면** 로그인 창에 "Google 계정으로 계속하기"가 나타납니다 → [아래](#google-로그인-켜기) |
| `PUBLIC_URL` | 없음 | 서비스 주소(`https://edulet.example.com`). 공유 링크·QR 의 주소와 Google 로그인의 돌아올 주소를 만드는 데 씁니다 |
| `GOOGLE_DOMAINS` | 없음 | 쉼표로 나눈 학교·기관 도메인(`school.ac.kr`) — 있으면 그 Google Workspace 계정만 로그인 |
| `MAX_UPLOAD_MB` | `20` | 업로드 한도 |
| `SESSION_DAYS` | `30` | 로그인 유지 기간 |
| `LINK_PREVIEW` | `1` | `0` 이면 서버가 외부 주소를 가져오지 않음(호스트 이름만 표시) |
| `TRUST_PROXY` | `0` | 리버스 프록시 뒤에서 `1` — `X-Forwarded-*` 를 믿고 접속자 IP·HTTPS 를 판별 |
| `COOKIE_SECURE` | `auto` | HTTPS 로 운영하면 `1` |

남용 방지 한도도 환경변수로 조절합니다(기본값과 뜻은 `docs/CONTRACT.md` §1): `GUEST_RATE`(IP당 게스트 참여/분, 기본 300 — 교실 하나가 공용 IP 를 써도 충분), `WRITE_RATE`(사용자당 쓰기/분), `UPLOAD_RATE` · `UPLOAD_QUOTA_MB` · `UPLOAD_CONCURRENCY` · `UPLOAD_PER_USER`, `SSE_PER_USER` · `SSE_PER_IP` · `MAX_CONNECTIONS`, `BOARD_MAX_POSTS`, `LOGIN_FAIL_MAX`, `MEMBER_RATE`.

> 공개 서버로 운영한다면: HTTPS + `TRUST_PROXY=1` + `COOKIE_SECURE=1`, 프록시에서 SSE 경로(`/api/boards/*/events`)의 응답 버퍼링을 끄세요(nginx: `proxy_buffering off;`). 누구나 쓸 수 있는 연습장이 필요 없으면 `SEED=0` 을 권합니다.

### Google 로그인 켜기

학생·교사가 새 비밀번호를 만들지 않고 **Google 계정으로 가입·로그인**하게 할 수 있습니다. 서버가 Google 에서 직접 인증 코드를 받아 처리하는 방식(OAuth 2.0 인증 코드 + PKCE)이라 **브라우저에 Google 스크립트가 올라가지 않고**, 키를 서버에 두는 것만 설정하면 됩니다. 키를 넣지 않으면 버튼 자체가 나타나지 않고 지금까지와 똑같이 동작합니다.

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 프로젝트를 만들고(또는 고르고) **OAuth 동의 화면**(Google Auth Platform)을 구성합니다. 학교 Workspace 안에서만 쓸 거라면 사용자 유형 **내부**, 아무 Google 계정이나 받으려면 **외부** 를 고르고 상태를 **프로덕션으로 게시**하세요(테스트 상태에서는 등록한 테스트 사용자만 로그인됩니다). 요청 범위는 `openid` · `email` · `profile` 세 가지뿐이라 별도 심사가 필요한 범위가 없습니다.
2. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기**에서 유형을 **웹 애플리케이션**으로 하고 **승인된 리디렉션 URI** 에 정확히 아래 주소를 넣습니다(`승인된 JavaScript 원본`은 필요 없습니다).
   - 운영: `https://서비스주소/api/auth/google/callback`
   - 내 컴퓨터에서 시험: `http://localhost:3000/api/auth/google/callback`
3. 발급된 **클라이언트 ID** 와 **클라이언트 보안 비밀**을 환경변수로 넘기고 서버를 다시 시작합니다. 운영에서는 `PUBLIC_URL` 도 함께 지정하세요(리디렉션 URI 가 환경마다 흔들리지 않고, https 주소면 로그인 쿠키에 `Secure` 도 붙습니다 — 그 상태로 http 로 접속해 시험하면 로그인이 안 되니 그때는 `EDULET_COOKIE_SECURE=0`).

```bash
EDULET_GOOGLE_CLIENT_ID=123-abc.apps.googleusercontent.com \
EDULET_GOOGLE_CLIENT_SECRET=GOCSPX-xxxx \
EDULET_PUBLIC_URL=https://edulet.example.com \
npm start

# Docker
docker run -p 3000:3000 -v edulet-data:/data \
  -e EDULET_GOOGLE_CLIENT_ID=... -e EDULET_GOOGLE_CLIENT_SECRET=... -e EDULET_PUBLIC_URL=https://edulet.example.com edulet
```

콘솔 메뉴 이름은 Google 이 자주 바꾸므로 위 이름과 다를 수 있습니다. 어긋났을 때는 서버 로그에 `Google token exchange failed: … redirect_uri_mismatch` 처럼 Google 이 알려 주는 이유가 남습니다(비밀 값은 남기지 않습니다).

- **학교 계정만**: `EDULET_GOOGLE_DOMAINS=school.ac.kr` 을 넣으면 그 Google Workspace 도메인 계정만 로그인됩니다. 서버는 이메일 주소 모양이 아니라 Google 이 보증하는 `hd`(도메인) 값으로 판정합니다. 일반 Gmail 도 받으려면 목록에 `gmail.com` 을 함께 적으세요.
- **계정 모양**: Google 로 처음 들어오면 계정이 새로 만들어집니다. 표시 이름은 Google 이름(나중에 프로필에서 바꿀 수 있음)이고, 보드에 초대받을 때 쓰는 아이디는 **무작위 `@g-…`** 입니다 — 이메일 주소를 공개 이름으로 쓰지 않으려는 선택이라, 초대하려는 사람에게 프로필에 보이는 아이디를 물어보세요. 비밀번호는 없습니다. 이메일은 본인 프로필에만 보이고 다른 사람에게는 절대 나가지 않습니다.
- **이미 비밀번호 계정이 있다면**: Google 로 처음 들어오면 *새 계정*이 만들어집니다(이메일이 같아도 자동으로 합치지 않습니다 — 남의 계정을 가로채는 길이 되기 때문). 기존 계정에 붙이려면 **기존 계정으로 로그인 → 프로필 → "Google 계정 연결하기"** 를 열고 **현재 비밀번호를 한 번 더 입력**하세요(남이 내 로그인 상태만 훔쳐서 자기 Google 계정을 몰래 붙이지 못하게 하는 확인입니다). 그 뒤로는 둘 중 어느 쪽으로든 같은 계정에 들어옵니다. 잘못 연결했다면 같은 곳의 "Google 연결 해제"(역시 비밀번호 확인)로 풀 수 있습니다 — 비밀번호가 없는 Google 전용 계정은 풀면 들어올 방법이 없어져서 풀 수 없습니다.
- `ALLOW_REGISTER=0` 이면 Google 로 *새로* 가입하는 것도 막히고, 이미 연결된 계정만 들어올 수 있습니다.
- 위 Pages 데모에서는 Google 로그인이 **없습니다**(서버가 없어 보안 비밀을 둘 곳이 없고, 데이터가 이 브라우저에만 있어 계정을 공유할 일도 없습니다).

## 구조

```
server/   Node 서버 — http.js(라우터) auth/google(Google 로그인)/boards/posts/sections/comments/reactions/uploads/preview(SSRF 방어)/realtime(SSE)/seed
public/   프런트 — js/lib(공용 기반·BoardController) js/views(앱 셸·페이지) js/board(보드 캔버스) css/ vendor/(QR)
          edulet-sw.js · demo/  Pages 데모용 서비스 워커 "서버"(IndexedDB 저장)와 부팅 스크립트
seed/     데모 보드 JSON + 이미지
test/     서버 테스트(node:test)      e2e/  브라우저 수락 시나리오(run.mjs 서버 모드 · pages.mjs 데모 모드)
tools/    cdp.mjs(크롬 구동기) · build-pages.mjs(정적 사이트 빌드) · backup.mjs(안전한 온라인 백업) 등
docs/     CONTRACT.md(서버↔프런트 계약)
```

실시간은 보드마다 SSE 연결 하나로 흐릅니다. 클라이언트는 **스트림을 먼저 열고 그다음 스냅샷을 받아** 그 사이의 변경을 놓치지 않으며, 연결이 끊기면 다시 붙을 때 스냅샷을 새로 받습니다. 모든 이벤트는 글 전체 상태를 담아 같은 글에 여러 번 적용해도 결과가 같습니다.

## 테스트

```bash
npm test         # 서버 단위·통합 테스트 (의존성·브라우저 불필요, 약 30초)
npm run e2e      # 실제 크롬 여러 개로 실시간·형식 전환·드래그 이동 등 (Chrome/Edge 필요, CHROME_PATH 로 지정 가능)
npm run e2e:pages  # Pages 데모 빌드를 /edulet/ 아래 정적 서버로 띄워 서비스 워커 부팅·탭 간 동기화·업로드·초기화 등 확인
```

E2E 는 `tools/cdp.mjs`(Node 22 내장 WebSocket 으로 크롬 DevTools 프로토콜을 직접 구동, 의존성 0)로 사용자마다 격리된 브라우저 컨텍스트를 만들어 실제 마우스·키보드 이벤트를 보냅니다.

## 보안 메모

- 비밀번호는 scrypt, 세션 토큰은 서버에 해시만 저장, 쿠키는 HttpOnly·SameSite=Lax. 상태를 바꾸는 요청은 Origin 을 확인합니다.
- Google 로그인은 서버가 인증 코드를 PKCE 와 함께 교환하고(`state`·`nonce` 는 요청한 브라우저의 HttpOnly 쿠키에 묶음, 1회용), 토큰의 발급자·대상·만료·nonce·이메일 확인 여부를 검사합니다. 진행 중인 로그인 정보를 담은 쿠키는 서버 비밀로 서명돼 있어 브라우저가 위조할 수 없고, 돌아갈 주소는 같은 사이트의 경로만, Google 토큰은 저장하지 않습니다. 기존 계정에 Google 을 붙이거나 떼려면 비밀번호를 다시 확인합니다.
- 사용자 입력은 항상 텍스트 노드/속성으로만 DOM 에 넣고(`innerHTML` 미사용), 링크는 `http(s)` 만 허용, 영상 임베드는 `youtube-nocookie`/`player.vimeo.com` 만 허용합니다. CSP 가 인라인 스크립트를 막습니다.
- 링크 미리보기는 서버가 외부 주소를 가져오므로 사설·루프백 주소와 리다이렉트를 모두 검사하고(SSRF 방어), 연결 시 검사한 주소로 고정합니다.
- 업로드는 매직 바이트로 이미지를 검증하고(SVG 거부) 이미지가 아닌 파일은 항상 내려받기로만 제공합니다.
- 계약 문서(`docs/CONTRACT.md`)에 권한표·API·이벤트가 정리돼 있습니다.

## 알려진 한계

Pages 데모는 위 표처럼 브라우저 한 곳에서만 동작하는 체험판입니다(비밀번호도 서버가 아니라 브라우저 안에서 PBKDF2 로 처리). 서버 모드는 서버 한 대·SQLite 한 파일 기준입니다(수백 명 동시 접속 교실 규모에 맞춤, 여러 서버로 나누려면 SSE 팬아웃을 바꿔야 함). 터치 화면에서는 카드를 끌지 않고 ⋮ 메뉴로 순서를 바꿉니다. 지도·타임라인 형식, 그림·녹음 첨부, 메일 알림, Google 외의 외부 로그인(카카오·네이버·Microsoft 등)은 만들지 않았습니다. Google 로그인은 진짜 Google 이 아니라 테스트용 가짜 Google 서버(`test/google-mock.js`)로 검증했습니다(키가 없어 실제 계정으로는 시험하지 못했습니다) — 처음 켤 때는 위 설정 뒤에 본인 Google 계정으로 한 번 로그인해 보세요.
